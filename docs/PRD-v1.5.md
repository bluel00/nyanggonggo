# PRD v1.5 변경분 – 상세를 목록 위에 얹기

## 0. 문서 정보

- 버전: v1.5 (초안, 2026-10-20)
- 상태: 요건 합의(EL), 구현 전
- 성격: 앞 버전에서 바뀌는 부분만 적은 변경 문서. 적히지 않은 것은 앞 버전이 그대로 유효하다. 저장소 `docs/architecture.md`가 이 문서보다 우선한다.
- 대체하는 곳: PRD-v1.4 3절 R1의 "보던 자리로 돌아가는 방법"(메모리 보관·스크롤 복원). R1의 목표("목록 → 상세 → 뒤로가기: 보던 자리로 돌아간다")와 R2(공유 링크)는 그대로다.
- 반영 대상: `docs/architecture.md` 7절(뒤로가기·스크롤 복원), 12절 37·56, 14절(4단계 전환)

## 1. 왜

- 아이폰 사파리에서 상세 → 목록을 쓸어넘기기로 돌아가면 카드 사진이 한 프레임 비어 깜빡였고, 그 직전에는 스크롤·터치가 먹지 않았다(EL 실기기, 화면 기록으로 확인). PC 브라우저와 헤드리스 WebKit에서는 재현되지 않는다.
- 원인: 상세로 갈 때 목록을 통째로 내리고, 돌아오면 다시 만든다. 사파리가 사진을 다시 디코딩하는 사이 빈 프레임이 그려진다. `decoding="sync"`는 실기기에서 효과가 없었다.
- 시험판(목록은 그대로 두고 그 위에 상세를 얹기)에서 깜빡임이 사라졌다(EL 실기기, 2026-10-20). Next.js 공식 문서가 같은 상황(피드 위에 사진을 띄우고, 공유·새로고침은 전체 페이지)에 intercepting routes + parallel routes를 권한다.
- 이 구조에서는 목록이 내려가지 않으므로 스크롤 복원 코드가 필요 없다.

## 2. 요구사항

### R1. 얹기
- 목록(`/`)과 찜(`/favorites`)에서 카드를 누르면 주소는 `/animals/{id}`로 바뀌고, 목록은 그대로 둔 채 그 위에 상세를 전체 화면으로 얹는다.
- 뒤로가기(화면 안 버튼, 브라우저, 쓸어넘기기)는 얹은 상세만 걷어 낸다. 아래 화면은 다시 만들지 않고, 스크롤 위치도 그대로다.

### R2. 직접 진입·새로고침·공유
- 공유 링크로 바로 들어오거나, 얹은 상세에서 새로고침하면 지금처럼 상세 전체 페이지다(PRD-v1.4 R2 그대로).
- 얹은 상세에서 새로고침한 뒤 뒤로가기를 누르면 목록을 처음부터 불러온다. 보던 위치는 보장하지 않는다(지금과 같음).

### R3. 얹은 동안
- 아래 목록은 스크롤되거나 눌리지 않는다. 상세는 자기 층 안에서 스크롤된다.
- 상세 맨 위에서 아래로 당겨도 페이지가 새로고침되지 않는다(상세의 스크롤이 바깥으로 이어지지 않게). 목록 화면의 당겨서 새로고침은 브라우저 기본 동작 그대로다. 실기기에서 확인한다.

### R4. 돌아온 직후
- 상세 층이 사라진 뒤 1프레임 안에 목록이 스크롤·터치된다. 사진이 잘리거나 비어 보이지 않는다.

### R5. 카드 → 상세 사진 전환
- 4단계 전환(카드 사진이 상세 사진 칸의 크기·위치로 옮겨 가며 자리를 잡음)을 새 구조에 맞게 다시 만든다.
- 새 구조에서 만들 수 없으면 디자인 시스템의 대체 동작(사진과 정보 200ms 페이드)으로 하고, 이유를 보고한다.
- 뒤로가기, 직접 진입, 종료 공고, 움직임 줄이기에는 효과가 없다(지금과 같음).

### R6. 걷어 낼 것
- 스크롤 복원 코드(픽셀 저장, 카드 가운데 맞춤, 관련 sessionStorage 키), 돌아올 때의 `decoding="sync"`, 이를 전제로 한 E2E.

## 3. 완료 기준

| 기준 | 확인 방법 |
|---|---|
| 목록·찜에서 상세를 얹고, 뒤로가기(버튼·브라우저) 후 아래 화면 요소가 같은 요소이고 스크롤 위치가 그대로 | E2E (Chromium, WebKit) |
| 뒤로가기 후 1프레임 안에 목록 스크롤 가능 | E2E (프레임 기록) |
| 얹은 동안 아래 목록이 스크롤·터치되지 않음 | E2E |
| 직접 진입·새로고침은 전체 페이지, R2(PRD-v1.4) 그대로 | E2E |
| 카드 → 상세 사진 전환(또는 대체 페이드), 효과 없는 경우들 | E2E |
| 스크롤 복원 코드·키가 남지 않음 | 검색 |
| 14.3 기준 전부(목록 스크롤, LCP, CLS, 카드 → 상세 보이기까지) | 실험실 측정 |
| 쓸어넘기기 깜빡임 없음, 돌아온 직후 바로 스크롤됨, 상세에서 당겨도 새로고침 안 됨 | EL 실기기(미리보기) |

## 4. 비범위

- 상세 안의 다음 층(사진 크게 보기를 방문 기록에 넣어 뒤로가기로 닫기 등)
- 댓글 등 새 기능

## 5. 결정 기록

| 항목 | 결정 | 이유 |
|---|---|---|
| 상세 여는 방식 | 목록 위에 얹기(intercepting + parallel routes) | 쓸어넘기기 깜빡임의 근본 원인 제거. 시험판에서 실기기 확인. Next.js 공식 권장 패턴 |
| 얹는 곳 | 목록과 찜 | 둘 다 카드 → 상세 화면이라 같은 동작이어야 한다 |
| 스크롤 복원 코드 | 걷어 냄 | 목록이 내려가지 않아 필요 없다. 남기면 엉뚱한 때 스크롤을 움직인다(시험판에서 확인) |
| 4단계 전환 | 새 구조에서 다시 만듦, 안 되면 페이드 | 디자인 시스템 A의 결정 유지 |
| 상세에서 당겨서 새로고침 | 막음(상세 층만) | 새로고침하면 얹은 구조가 풀려 목록을 잃는다 |
| `decoding="sync"` | 걷어 냄 | 실기기에서 효과 없음 |
