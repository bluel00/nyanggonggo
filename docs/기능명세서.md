# 기능명세서 v1.0 (MVP) – 유기묘 공고 모바일 웹

## 0. 문서 목적

- PRD의 목표(사진 중심 소비 + 공유 유도)를 **화면/기능/데이터/상태/예외처리**로 구체화
- 구현 시 “논쟁 포인트”를 미리 결정/보류로 분리

---

## 1. 범위

### 1.1 In Scope (MVP)

- 목록 `/animals` : 무한 스크롤, 카드 피드, 필터 바텀시트(적용 버튼)
- 상세 `/animals/{id}` : 사진 스와이프, 핵심 정보, 공유(카카오 우선 + 링크 복사 fallback), 찜
- 이미지 풀스크린 뷰어 : 사진 감상 중심
- 찜 목록 `/favorites` : 로컬 저장 기반, 빈 상태
- 서버 프록시/캐시(BFF): 공공 API는 Next 서버에서만 호출, 서버 캐시 + 정렬/필터/커서 처리 (PRD 4.1-7)

### 1.2 Out of Scope

- 로그인/회원/입양 신청/연락처 노출/알림/커뮤니티
- AI 문구 자동 생성, 인스타/X 공유 확장

## 2. 공통 UX/디자인 규칙 (MVP 기준)

### 2.1 레이아웃/간격

- 기준 폭: 390px (iPhone 14). PC는 max-width 480px 컬럼 중앙 정렬 (별도 레이아웃 없음)
- 좌우 패딩 16px / 카드 간격 12px / radius 16px
- iOS Safe Area 고려 (하단 CTA 영역 padding)

### 2.2 상태 표현

- 보호 상태/종료/D-day는 **사진 위 오버레이**로 0.5초 내 인지
- 포인트 컬러는 “상태”에만 사용 (브랜드 컬러 과사용 금지)
- 종료 공고는 status 필터로 표시하며 종료 사유(안락사, 자연사 등)는 노출하지 않는다

### 2.3 모션

- 카드 클릭: 100ms scale-down
- 바텀시트: ease-out slide
- 사진 전환: swipe 자연스러운 애니메이션
- 모션은 “보조” (과한 애니메이션 금지)

## 3. URL / 상태관리 정책

### 3.1 라우팅

- `/animals`
- `/animals/{id}`
- `/favorites`

### 3.2 Search Params (목록 = Single Source of Truth)

- `species`: `cat | dog` (기본 `cat`)
- `region`: string (시도 코드 `upr_cd`, UI에서 라벨 매핑)
- `status`: `protected | ended | all` (기본 `protected`)
- `sort`: `latest | endingSoon` (기본 `latest`)
- `page`: URL에 넣지 않는다 (무한스크롤 내부 커서, `useInfiniteQuery`로 관리)

> 원칙: UI 내부 상태로 필터를 들고 있지 않고, **URL 변경 → 목록 리로드**가 기준.

## 4. 화면별 기능 명세

## 4.1 고양이 목록 `/animals`

### 4.1.1 사용자 목표

- 사진을 빠르게 소비하면서 “괜찮은 고양이”를 발견
- 필요한 경우만 필터로 탐색
- 공유/찜은 “가벼운 행동”으로 제공

### 4.1.2 화면 구성

- 상단: 타이틀 “고양이 공고” + 필터 버튼(아이콘+텍스트)
- 본문: 카드 1열 피드, 무한 스크롤
- 하단 탭바 없음

### 4.1.3 카드 UI/데이터

카드 구성:

- 메인: 사진(4:5, `object-cover`, 초점 위쪽. 풀스크린 뷰어는 원본 비율)
- 오버레이: `보호중/종료` + `D-day`(종료 기준)
- 하단 텍스트(최소):
    - 1줄: 이름(없으면 지역명/발견장소 요약)
    - 2줄: 지역 · 보호소

카드 동작:

- 카드 전체 클릭 → 상세 `/animals/{id}`
- 카드 내 작은 CTA(옵션):
    - 찜(🤍) 아이콘은 **카드 내부에 넣을지/상세에서만 둘지 결정 필요**
    - 공유는 목록에선 제외(상세 중심)

### 4.1.4 무한 스크롤

- 최초 진입 시 1페이지 로드
- 하단 근접 시 다음 페이지 자동 요청
- 로딩 상태: 스켈레톤 카드(이미지 회색 박스)
- 에러 상태: “지금은 고양이를 불러오지 못했어요” + 재시도 버튼
- 끝(더 없음): “끝났다” 느낌을 주지 않기 위해
    - **옵션 A:** 조용히 로드 중단(표시 없음)
    - **옵션 B:** 아주 약한 “더 이상 공고가 없어요” 1줄  
        → **결정 필요(디자인 원칙상 A 추천)**

## 4.3 상세 `/animals/{id}`

### 4.3.1 화면 구성

- 상단: Back

- 핵심 정보(상단 가까이):

    - 보호소
    - 발견 장소
    - 공고 기간

    - 🤍 찜
    - 카카오톡 공유

    - 로그인 없이 localStorage 저장

    - 카카오 공유 SDK 호출(성공/실패 처리)

### 4.3.3 데이터 로딩

- 상세 진입 시 id로 상세 조회
- 목록에서 넘어올 때 “프리패치/캐시 사용” 가능(성능 옵션)

### 4.3.4 예외/빈값 처리

- 이름 없음 → “지역명” 또는 “발견장소 요약”
- 사진 없음 → 기본 플레이스홀더 이미지(혹은 빈 이미지 상태) **결정 필요**
- D-day 계산:
    - 종료일 기반 `D-n`, 당일 `D-day`, 지남 `종료` 처리 정책 **결정 필요**

## 5. 도메인 모델/데이터 명세 (Hexagonal 원칙 반영)

### 5.1 Domain Model (내부 표준)

예시(개념):

- `Animal`
    - `id: string`
    - `species: 'cat' | 'dog'`
    - `images: string[]`
    - `status: 'protected' | 'ended'`
    - `noticeEndAt: Date | null`
    - `sex: 'male' | 'female' | 'unknown'`
    - `ageText: string | null`
    - `regionText: string`
    - `shelterName: string | null`
    - `foundPlaceText: string | null`
    - `noticePeriodText: string | null`

> 핵심: **외부 API DTO를 그대로 UI에 흘리지 않고**, Mapper에서 우리 도메인으로 “통역”합니다.

### 5.2 DTO & Validation

- 외부 API 응답은 DTO 타입으로만 존재
- DTO는 Zod로 “도착 검증”만 수행
- 가공/재구성/파생(D-day 등)은 Mapper/Domain 서비스에서 수행

## 6. 기능 요구사항 상세 (유스케이스 관점)

### UC-01 목록 조회

- 입력: URL params
- 출력: 카드 리스트
- 성공: 스켈레톤 → 데이터 렌더
- 실패: 에러 메시지 + 재시도
- 무한스크롤: nextPage 존재 시 계속 로드

### UC-02 필터 적용

- 입력: 바텀시트 선택값
- 처리: URL params 갱신 → 목록 refetch
- 취소: 적용 전 닫기 시 변경 무시

### UC-03 상세 조회

- 입력: path param `{id}`
- 출력: 이미지/상태/정보/CTA
- 실패: “지금은 고양이를 불러오지 못했어요” + 뒤로가기

### UC-04 찜 토글

- 입력: animal id
- 저장: localStorage
- 출력: 즉시 UI 반영 + favorites 반영

### UC-05 공유

- 입력: animal id, 공유 메타(제목/썸네일/링크)
- 처리: Kakao SDK → 성공/실패
- 실패: 링크 복사 fallback + 토스트

## 9. FSD + Hexagonal 매핑 (구현 가이드)

### 9.1 레이어 책임

- `pages`(코드에서는 `views`, Next의 pages 폴더와 충돌 회피): 라우팅/레이아웃/배치만
- `features`: 필터, 공유, 찜, 무한스크롤 컨트롤 등 “사용자 행동 단위”
- `entities`: Animal 도메인 모델, mapper, repository interface(Port)
- `shared`: UI 컴포넌트, lib, api client, zod schemas, utils

### 9.2 Ports & Adapters (핵심)

- Port (Interface): `AnimalRepository`
    - `getAnimals(params): Promise<AnimalPage>`
    - `getAnimalById(id): Promise<Animal>`
- Adapter:
    - 브라우저 → 자체 `/api/**`(BFF) 호출 → WireDto zod 검증 → 클라이언트 Mapper → Domain 반환
    - 공공 API 호출, UpstreamDto(1:1) 검증, 서버 Mapper, 캐시는 서버(`src/server`)에서 처리 (상세: `docs/architecture.md`)

> UI/React Query는 “어댑터/유틸”일 뿐, 도메인을 끌고 다니지 않게.

# 지금 시점에서 “결정이 필요”한 것들 (최소만 뽑음)

1. **기본 필터 값** → 결정: `protected`

- status 기본을 `all`로 갈지 `protected`로 갈지
    - 디자인 목표(피드 소비) 기준: `all`이 더 “콘텐츠 피드” 느낌
    - 입양 탐색 성격을 줄이려면 `all`이 안전

2. **페이지(page) 파라미터를 URL에 유지할지** → 결정: URL 미포함, 내부 커서

- 무한스크롤에서 `page`를 URL에 계속 반영하면 “공유/뒤로가기” 경험이 복잡해질 수 있어요.
    - **추천:** 필터/정렬만 URL, page는 내부 상태(딥링크는 `/animals?…`까지만)

3. **region 값의 표현** → 결정: 시도 코드 + UI 라벨 매핑

- URL에 “코드”를 넣을지, “한글 지역명”을 넣을지
    - **추천:** 코드(짧고 안정적) + UI에서 라벨 매핑

4. **찜 저장 정책** → 결정: id만 저장

- id만 저장 vs 카드 최소 정보 캐시 저장
    - **추천:** 최소 캐시 저장(썸네일/상태/지역/보호소) + 상세 진입 시 최신 갱신

5. **사진 없는 공고 처리**

- placeholder 이미지 제공 여부(UX/감성에 영향 큼)
