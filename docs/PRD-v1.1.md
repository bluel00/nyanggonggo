# PRD v1.1 변경분 – 기타 축종 · 홈 화면 · 축종 기억

## 0. 문서 정보

- 버전: v1.1 (확정, 2026-10-02)
- 성격: PRD v1.0(`PRD.md`)에서 바뀌는 부분만 적은 변경 문서. 충돌하면 이 문서가 우선한다.
- 반영 대상: PRD 3·4·5절, 기능명세서, 저장소 `docs/architecture.md` 7절
- 상태: 기타 축종(4.1-2)은 구현·배포 완료. 홈 화면·축종 기억은 미구현.

---

## 1. 변경 이유

- 축종에 기타가 추가되어 축종이 세 개가 되었다. 실측(2026-10-01) 비율은 개 63% / 고양이 35% / 기타 2.3%로, 기본 축종(고양이)이 다수 사용자의 관심과 어긋날 수 있다.
- 처음 온 사용자는 무엇을 볼지 직접 고르게 하고, 다시 온 사용자에게는 단계를 더하지 않는다.
- 사진이 없는 화면을 하나 두어, 이후 캐릭터 애니메이션(Rive)이 들어갈 자리로 쓴다.

---

## 2. 사용자 흐름 (3.1 변경)

```text
첫 방문 (축종 기억 없음)
 → 홈: 고양이 / 강아지 선택 (기타는 텍스트 링크)
   → 그 축종의 목록 (기억된 지역, 없으면 서울)

재방문 (축종 기억 있음)
 → 바로 그 축종의 목록

공유 링크 진입
 → 상세 (홈을 거치지 않음)
   → 뒤로가기: 그 공고의 목록 (축종·지역을 기억하지 않음)

목록에서 축종 바꾸기
 → 목록의 홈 진입점 → 홈에서 다시 선택
 → 또는 필터 시트에서 바로 변경
```

---

## 3. 기능 요구사항 (4.1 변경·추가)

### 2) 필터 기능 – 축종 (변경, 구현 완료)

- 축종: 고양이 / 강아지 / 기타 (`cat | dog | other`)
- 기타 공고는 카드·상세·공유에서 어떤 동물인지(`kindFullNm`에서 추출, 예: 토끼) 보여준다. 특정할 수 없으면 "기타 동물".
- 여러 축종이 섞이는 화면(찜 목록)은 축종 중립 문구("찜한 공고")를 쓴다.

### 7) 홈 화면 (신규)

- 고양이와 강아지를 큰 선택지 2개로 둔다. 선택지마다 캐릭터 일러스트가 들어간다(1차는 정지 SVG).
- 기타는 같은 무게의 선택지로 두지 않고 아래에 작은 텍스트 링크로 둔다(예: "다른 동물들도 있어요").
    - 근거: 기타는 전체의 2.3%, 서울 보호중 18건이라 같은 무게로 두면 빈 목록에 가깝다.
- 기타 캐릭터는 만들지 않는다. 종 분포가 분산되어(최다 토끼 21%) 하나로 대표할 수 없다.
- 사진이 없는 화면이다.
- 선택지는 일러스트만이 아니라 텍스트 라벨("고양이", "강아지")을 가진 버튼이다.
- 우선순위: 중

### 8) 축종 기억 (신규)

- 사용자가 홈 또는 필터 시트에서 축종을 **직접** 고르면 기억한다(지역 기억과 같은 쿠키 방식).
- 공유 링크 진입, focus로 돌아온 목록에서는 기억하지 않는다(지역과 같은 규칙).
- 축종 기억이 있으면 홈을 건너뛴다.
- 목록에서 홈으로 돌아가는 진입점을 둔다. 위치는 디자인에서 정하되, 사용자가 알아볼 수 있어야 한다.

## 4. URL (5절 변경)

- 목록: `/` (유지)
- 홈: `/home` (신규)
- 상세: `/animals/{id}` (유지)
- 찜: `/favorites` (유지)

규칙:

- 앱이 만드는 목록 주소에는 지역과 마찬가지로 **축종도 늘 명시**한다. 축종 기억이 생기면 축종 없는 주소의 뜻이 "기억된 축종"이 되기 때문이다.
- 축종이 없는 목록 주소로 들어오면:
    - 축종 기억이 있으면 그 축종을 채워 리다이렉트(지역 리다이렉트와 같은 방식)
    - 축종 기억이 없으면 `/home`으로 보낸다
- v1.0 5.2의 `page` 파라미터는 삭제(내부 커서로 관리, URL 미포함).

## 5. 비범위

- 캐릭터 애니메이션(Rive): 홈이 정지 SVG로 배포된 뒤 별도 단계에서 진행한다. 찜 목록 빈 상태 실험은 홈 캐릭터로 대체한다.
- 서비스 이름 변경, 기본 축종 변경
- 홈에 추천 공고·통계 등 콘텐츠 추가
